# Screenshots

Place your application screenshots in this folder.

## Naming Convention

Name your screenshots sequentially so they appear in logical order:

  01-command-center-dashboard.png  ← Threat posture: 248 alerts → 9 incidents → 1 critical
  02-priority-threat-incident.png  ← INC-001 critical: SERVER-17, 94% confidence
  03-incident-queue.png            ← Prioritised queue of correlated incidents

  04-alert-explorer.png            ← Raw multi-source alerts, uncorrelated noise
  05-alert-filter-server-17.png    ← Same explorer filtered to the SERVER-17 chain
  06-incident-explorer.png         ← Correlated incidents: requires action vs monitor

  07-investigation-bluf.png        ← BLUF summary at the top of the investigation view
  08-evidence-trail.png            ← Alert-level evidence the incident is grounded in
  09-mitre-attack-mapping.png      ← MITRE ATT&CK techniques and the attack chain
  10-recommended-actions.png       ← Recommended response actions for the commander

  11-analysis-run-complete.png     ← Analyze Alerts: correlation pipeline result
  12-ibm-granite-bluf.png          ← IBM Granite generating the BLUF (IBM technology)
  13-backend-api-docs.png          ← FastAPI /docs — the canonical D2 API
  14-light-theme-dashboard.png     ← Light theme: same data, bright-room view

## Requirements

- Minimum: 3 screenshots
- Format: PNG or JPG
- Show the application running with real (or realistic mock) data
- Avoid screenshots of empty states or placeholder data
- Captions are not required but appreciated

## Tips

- Use a consistent browser window size across all screenshots
- Highlight key UI elements with arrows/circles if helpful (use any image editor)
- Include a screenshot showing IBM technology integration if applicable
